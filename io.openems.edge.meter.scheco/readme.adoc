= Meter Scheco

Reads electricity and heat sub-meters from a Scheco AG Modbus/TCP gateway.

[NOTE]
====
Superseded by `io.openems.edge.meter.modbus`, which reads the same gateway
from configuration. This bundle is retained only so that already-deployed
gateways keep running; the two run side by side and do not interfere.

Configure new installations with the generic bundle, and migrate existing ones
using link:../docs/migrations/2026-08-04-scheco-to-meter-modbus.md[the migration
notes], which map every sub-meter onto its generic equivalent.
====

The gateway is a single Modbus slave (default unit-id 10) that exposes 12
sub-meters. Each component instance reads exactly one sub-meter and maps it onto
the standard `ElectricityMeter` channels. Add one instance per sub-meter, all
pointing at the same Modbus bridge.

Each sub-meter occupies 4 contiguous holding registers (read via FC3): a 32-bit
energy value (1/10 kWh) followed by a 32-bit power value (W). Both are read as
signed values in the Modbus default word order (MSWLSW); register addresses,
scale and word order follow the vendor specification in
link:../docs/vendor/scheco.pdf[`docs/vendor/scheco.pdf`].

This bundle is consumption-oriented (default `MeterType.CONSUMPTION_METERED`,
where positive power means consumption). The gateway exposes a single cumulative
counter per sub-meter, which grows while the power is positive. Following the
OpenEMS `ElectricityMeter` convention, it is mapped to `ACTIVE_PRODUCTION_ENERGY`
(scaled to Wh) for every meter type, and power to `ACTIVE_POWER`. For a
consumption meter, `ACTIVE_PRODUCTION_ENERGY` therefore holds the consumed
energy. `ACTIVE_CONSUMPTION_ENERGY` stays undefined. The `invert` option negates
only the power sign (e.g. to correct a reversed measurement convention); it does
not move energy between channels, as a single counter cannot be split into
import/export.

Upgrading: energy moved from `ACTIVE_CONSUMPTION_ENERGY` to
`ACTIVE_PRODUCTION_ENERGY`; ship this bundle together with the matching ROOCKiE
gateway release.

The 5 `HEAT_*` sub-meters are thermal (Wärmezähler); as OpenEMS has no
heat-meter nature they map onto the same generic W/Wh channels.

The `CUSTOM` sub-meter option reads a user-defined register pair: the config
property `customEnergyAddress` (0-65533) is used as the energy register
address and the power value is read at address + 2, with the same format as
all documented sub-meters. This allows reading pairs added in future revisions
of the vendor register list without a software update.
